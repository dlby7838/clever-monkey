# P2：本地语义检索与快速预览

Lite 2.1仍是主打标模型，flex、关闭思考、中文输出。本阶段复用已有100条结果，不重复调用视频理解API，不访问NAS。2026-10-20已移除人工反馈的页面、写入和导出接口，不再创建反馈表；历史表不主动删除，不用于检索。

## 启动

使用项目根目录运行；已有的100条本地原片、评测结果、数据库和模型均在Git忽略的 `data/` 内。

```bash
uv venv .venv
uv pip install --python .venv/bin/python -e '.[semantic]'

# 新环境首次导入；已有库无需重导，重导不会产生重复分析。
.venv/bin/python -m material_search.cli import \
  --comparison data/evaluations/oatmeal-100-report/results/comparison.json \
  --run data/evaluations/oatmeal-100-zh-lite-flex-20261020/report.json \
  --manifest data/testsets/oatmeal-100-20261019/manifest.json

# 首次下载本地模型并建立向量，之后增量索引只处理新内容。
.venv/bin/python -m material_search.cli index
.venv/bin/python -m material_search.cli serve \
  --media-root data/testsets/oatmeal-100-20261019/videos --port 4174

.venv/bin/python -m material_search.cli search '把商品放进购物车'
.venv/bin/python -m material_search.cli search '拿勺子盛起一口酸奶' --mode semantic
.venv/bin/python -m material_search.cli search '燕麦 倒入' --mode keyword --limit 5
```

浏览器打开 `http://127.0.0.1:4174/`。没安装uv时，可用 `python3 -m venv .venv` 和 `.venv/bin/python -m pip install -e '.[semantic]'`。自定义数据库须把 `--db 路径` 放在子命令前；`index/search/serve`均支持 `--model-cache`，默认 `data/models`。只需要旧关键词命令时不必安装semantic依赖。

## 数据库与证据

默认 `data/materials.sqlite`，继续使用SQLite。分析表保留SHA256、源文件映射、原始输出、费用/usage、模型、提示词与预处理配置、校验状态。同证据指纹去重；新证据保留新版本，搜索各素材/模型最新导入版本。历史失败尝试独立保存，错误不被误当作成功分析。

导入仅读取三个JSON文件并校验清单映射，不访问原片、不重新计算原片哈希。来源完整性沿用P1指纹。可指定扫描器的SQLite库，按SHA实时关联移动后的登记路径；独立库中的NAS路径只是来源记录，不代表NAS在线。

新增 `search_vectors`：按分析版本、段落编号、模型权重/分词器指纹、索引配置版本保存little-endian float32向量与文本哈希。段落包括摘要/主体/动作、详细画面描述、动作时间段及单独的OCR；OCR默认不参与召回。重建本轮索引新增0条。

## 语义和混合检索

- 模型是 `BAAI/bge-small-zh-v1.5`，512维，FastEmbed 0.7.4/ONNX本地推理。Lite用于视频描述，BGE用于文本向量，两者用途不同。
- 首次 `index` 从FastEmbed官方模型来源下载约90MB权重/分词器并持久保存。`serve/search`只加载本地已有文件；素材描述和查询不上传远程服务，无向量API费用。
- 对摘要、主体、动作、详细画面描述 `visual_description` 及各时间段分别向量化，避免长素材只保留开头；正文有512 token截断和字符限额，无法保证覆盖所有细节。详细画面描述按350字符、步长300字符分段，避免长描述尾部遗漏。OCR独立分段；画面描述中的背景信息默认参与语义和关键词匹配。
- 在所有符合主体/动作/时长/状态过滤条件的最新分析中做精确余弦检索，不先截断成前100条再做语义排序。一个素材取最匹配段落，返回对应原始动作文字和可用时间。
- `semantic`按余弦排序；默认 `hybrid`在余弦基础上加入摘要、主体、动作、详细画面描述的中文双字词覆盖、常见动作同义词及有限的倾倒对象方向提示。提示是可检查的词法排序规则，不是新的视觉判断。保留 `keyword`模式作为字面AND匹配基线。
- 相似度不是概率/准确率。当前0.45为初始余弦过滤阈值，未用独立真值集校准；无匹配与相似干扰场景均可能判断错误，特别是动作对象、方向、否定和背景信息。页面不显示虚假的准确率。
- 模型未安装、权重改变、索引缺失或新增分析尚未建立向量时，明确报错并提示重建；不悄悄将关键词结果冒充语义结果。关键词模式仍可独立运行。
- 当前在SQLite中保存向量，进程内精确计算；适合现有100条验证。大规模扩展前再评估分批读取/矩阵缓存、SQLite向量扩展或PostgreSQL/pgvector，不把现有耗时直接外推10,000条。

模型依据：[BAAI模型卡](https://huggingface.co/BAAI/bge-small-zh-v1.5)、[FastEmbed支持列表](https://qdrant.github.io/fastembed/examples/Supported_Models/)。

## 快速预览与安全

旧路径先完整转码720p，再整段下载成Blob后才能显示。新路径直接向浏览器输出fragmented MP4，边转码边播放，不生成临时文件、不创建持久视频缓存。

- 预览默认480p、24fps、H264、无音频，保持方向与比例、不放大原片。P1分析压缩仍为原720p配置，不受影响。
- Mac启动时探测VideoToolbox编码能力，优先硬件解码/编码；首包前失败会尝试一次软件编码，软件使用2线程和ultrafast。其他平台直接软件编码，不保证同等耗时。
- 点击动作时间段使用服务器输入前寻址，从该原片时间流式播放，无需先下载前面的整段。原生播放器时间从这段流的0秒计，画面下方显示原片时间；流式模式下原生拖动条对未缓冲部分可能受限，可用时间段按钮跳转。
- 同时仅一个转码，切换素材或离开页面断开旧播放；传输断开后终止FFmpeg并释放锁，最长180秒进程超时。快速切换可能提示短暂忙碌，允许重试。仅做本地预览，不对NAS预读或后台批量转码。
- 仅允许已入库 `local` 路径且在指定媒体根目录内；拒绝路径越界、符号链接、硬链接和网络挂载，不回退读NAS。原片只作FFmpeg输入。
- 数据库和模型缓存沿用本地文件系统保护。只监听127.0.0.1，校验Host/Origin，预览使用页面会话令牌；不提供任意路径静态服务。不适合直接公网部署。
- 模型原始时间段不被改写。零长度/逆序段不可点击；基础校验通过不等于内容识别正确。

## 验证与限制

已用实际100条建立本地向量，整句“把商品放进购物车”可召回对应购物车素材，“拿勺子盛起一口酸奶”可召回舀酸奶素材，“几份早餐摞在一起”默认混合排序首条为三碗堆叠素材。这是功能示例，不代表完成正式检索质量验收。

同机3条原片（3.6、10.08、4.65秒）对比：旧720p完整预览准备8.922、32.181、10.960秒；新480p硬件流式首个完整视频片段1.022、0.806、0.784秒。测量不含浏览器额外缓冲，且受分辨率、机器、源编码和负载影响；不能承诺所有素材1秒内播放。明细本地 `data/previews/preview-speed.json`。浏览器在购物车素材上实测首帧1.364秒；131.4秒长素材经HTTP返回前32KiB用时0.730秒，后者仅验证无需等待整段，不代表首帧播放耗时。

本轮70项测试通过。运行测试：`python3 -m unittest discover -s tests`，基础测试不下载模型、不调用API。覆盖向量增量幂等、语义召回/模式切换、OCR隔离、版本/权重/维度失配、过滤条件、反馈接口移除、路径/跨站保护、真实FFmpeg流输出、寻址参数和原片SHA不变。

下一步是独立查询集上的检索验证与排序优化；不恢复人工反馈工作流，不启动全量NAS分析或自动剪辑。
