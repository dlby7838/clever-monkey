# P2：素材检索验证

2026-10-20用户确定Seed2.1 Lite为后续主打标模型，版本doubao-seed-2-1-lite-260915，默认flex、关闭思考、中文输出。不支持或失败时进入记录/复核，不自动切到常规档或Pro。当前本地.env已记录模型，不启动新的付费调用或全量NAS分析。

## 目标

从自然语言需求找到合适镜头，并查看原始描述、动作、时间段、相关性和视频预览。先复用已付费的100条Lite结果验证检索，再扩展NAS素材库。不进入自动编导/成片阶段。

## 实施顺序

1. **统一分析结果入库**：导入现有100条Lite原始输出、独立校验结果、usage和来源指纹。以素材SHA256关联文件登记，保留模型版本、提示词版本、预处理版本、原始JSON、规范化字段、复核状态和NAS来源映射。导入可重复执行且不产生重复记录，不重跑视觉分析。
2. **检索数据整理**：主体与动作独立于背景描述、背景OCR；保存模型原文，不把缺字段/舍入与动作错误混淆。Lite样本11的零长度时间段标记待复核；不因此删除整条素材描述。标记身份/功效/音频推断风险，人工修订另存版本，不覆盖原始证据。
3. **建立搜索基线**：先用本地SQLite全文与结构化筛选验证入库及基础搜索，支持主体、动作、方向、时长、复核状态等实际有数据的条件。接着比较文本向量与关键词融合检索；向量模型接入前另核对可用性与费用，不把视频模型当作向量模型。
4. **最小检索页面**：输入需求，显示候选视频、相关描述和动作时间段，支持预览、人工标记相关/不相关及查看原始结果。预览优先本地测试集，后续接NAS时严格只读并复用本地限速缓存，NAS不写缩略图/描述/数据库。
5. **验收与扩展**：准备约30条真实检索需求，分开发查询与保留验收查询，人工标注相关片段。建议验收目标为保留查询中至少80%能在前5条找到有用镜头；这是目标而非实测结果。分别检查静态物品、动作区别、背景电视、非食品人物镜头和无匹配需求。通过后再决定PostgreSQL/pgvector及更大规模入库，而非先迁移全部服务。

## 第一项具体开发

实现“现有Lite评测结果导入器＋统一素材分析表＋离线检索命令”，验证100条原文和来源均可追溯、重复导入不重复登记、失败状态不丢失。然后搭建搜索页面和语义向量对比。

所有工作优先复用本地数据；NAS范围仍仅抖音自播及子目录视频，不变更原片。临时视频代理用后清理。P2结果不能代替精确动作时间真值或证明已经具备自动剪辑质量。

## 已完成：离线导入和关键词搜索（2026-10-20）

新增 `material_search`，标准库实现，无新增依赖和付费调用。数据库默认 `data/materials.sqlite`；可用 `--db` 指定现有扫描器SQLite库，同库时按SHA256实时查询扫描登记和移动后的路径，不修改扫描表。独立库只保留测试集和NAS来源映射，不代表已验证NAS在线。

安装项目后可用 `material-search`；也可在项目根目录直接执行：

```bash
python3 -m material_search.cli import \
  --comparison data/evaluations/oatmeal-100-report/results/comparison.json \
  --run data/evaluations/oatmeal-100-zh-lite-flex-20261020/report.json \
  --manifest data/testsets/oatmeal-100-20261019/manifest.json

python3 -m material_search.cli search '燕麦 倒入' --limit 5
python3 -m material_search.cli search '勺子' --subject '碗' --min-duration 3 --max-duration 20
python3 -m material_search.cli search '' --review needs_review
```

搜索结果为JSON，包含原始输出、时间段、校验、usage、模型/提示词/预处理配置、SHA256及本地/NAS来源路径。导入仅读取三个JSON文件，不访问视频、不重新计算原片哈希；来源完整性沿用P1已验证的指纹，导入时检查清单映射一致。数据库输出沿用P0本地文件系统、符号链接和硬链接保护；禁止写入素材目录或网络共享。

- 每条分析按完整证据指纹去重，原文不可变；不同证据保留为新版本，搜索每个素材/模型最近一次导入的新版本。重导旧证据不切换当前版本。
- 失败尝试独立保存，不能视为成功分析。此次100条分析、101条尝试（含历史欠费拒绝）全部保留。
- 99条为内容尚未人工验收，1条机械校验异常待复核；这不表示99%内容准确。轻微时间舍入警告保留原校验分类，不自动升级为动作识别错误。
- SQLite FTS5中文双字索引加速，搜索按**空格分隔的关键词全部字面出现**筛选；单字/英文退回字面匹配。不是语义搜索，不支持同义词或整句意图理解。排序仅为关键词相关程度，不是置信度。需SQLite支持FTS5。
- 默认不检索 `visible_text`；`--include-ocr` 显式加入。描述中仍可能混入背景或模型推断，未自动完成前景/背景事实分离，结果需要人工判断。
- 支持主体、动作、时长、复核状态筛选；时间段在原文证据中展示，尚不按片段独立召回。不虚构缺失的方向标签。
