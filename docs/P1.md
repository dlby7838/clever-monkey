# P1：视频理解验证

## 当前状态

P0 本地测试已通过，NAS 实机只读访问、并发上传下载影响、真实断连保护仍为**待验收项**，留待具备 NAS 环境后验证。开始 P1 不代表 P0 已完成生产验收。

P1 已实现单条本地短视频分析、mock/Ark 两种提供方、结构化校验、SQLite 保存、内容与配置缓存，以及 token usage 和请求耗时登记。尚未调用真实 API，未证明模型理解质量。当前单条命令便于逐条审阅，不包含自动批量付费或自动重试。

## 不需要 NAS 的本地试跑

准备一条已存在本地磁盘的 MP4/MOV/WebM 样本，推荐 5～10 秒。原片不再受 40 MiB 限制；默认最长 30 秒。分析前自动转成 H.264/720p 压缩副本，压缩副本必须不超过 40 MiB，避免误传大素材。不要直接指向 NAS，P1 本身不提供 SMB 限速。

```bash
python3 -m video_understanding.cli \
  --video '/本地路径/sample.mp4' \
  --provider mock \
  --database './data/p1.sqlite3'
```

mock 不联网、不调用 AI，只生成明显标记的占位结果。它只能验证流程，不能用来评价视频理解能力。相同内容和配置再次执行返回 cached=true。

## 接入火山方舟

适配器依据官方 Chat API 视频输入格式，以 Base64 内联传入视频并指定 fps，使用 JSON object 输出。模型必须支持视频输入和 JSON 模式；具体可用模型/接入点 ID 以你的方舟控制台为准，不在代码中固定模型版本。

官方参考：
- https://docs.volcengine.com/docs/ark/video-understanding?lang=en
- https://docs.volcengine.com/docs/ark/chat-api?lang=zh&redirect=1
- https://docs.volcengine.com/docs/ark/add-json?lang=zh

在火山方舟控制台开通适用模型并创建 API Key，将密钥置于当前终端环境变量 `ARK_API_KEY`，模型 ID 置于 `ARK_MODEL`。不要把真实密钥写进 Git、截图或聊天。命令行会自动读取项目根目录的 `.env`（仅支持 ARK_API_KEY、ARK_MODEL，权限必须为 600）；已有环境变量优先。配置文件已被 Git 忽略，不会作为代码提交。

模型 ID 示例为占位值，需替换：

```bash
export ARK_MODEL='你的模型或接入点ID'
python3 -m video_understanding.cli \
  --video '/本地路径/sample.mp4' \
  --provider ark \
  --fps 1 \
  --database './data/p1.sqlite3'
```

显式选择 ark 会将视频发送到火山方舟并可能产生费用。未配置密钥不会降级为模拟成功，会直接报错。接口固定使用 HTTPS 北京区域官方端点；无自动重试，超时不代表服务端没有计费。视频上传与推理可能需要比默认 60 秒更长的 `--timeout`。

结果中的 usage 原样保存，模型不返回时为空对象；不按未经确认的单价猜测人民币费用。缓存键包含原片 SHA256、提供方、模型 ID、fps、提示词版本和压缩配置版本；mock 与真实结果隔离。失败和校验不通过的结果不会写入成功缓存。升级提示词时须更新 PROMPT_VERSION。

## 输出和检查

输出包含 summary、visual_description、subjects、actions、shot_type、camera_motion、visible_text、timeline、uncertainties。timeline 使用秒数，校验边界、顺序和重叠；其精度仍需要人工核对。只分析画面，不提供音频转录。提示词要求保留客观详细描述、不确定信息明确记录、不编造品牌和功效。

本地 SQLite `analyses` 保存描述、usage、耗时、内容指纹和模型信息，不保存原视频或 API Key。命令行输出含素材描述，日志也应视为素材数据保护。当前失败仅通过退出码 2 与错误信息报告，没有失败记录表；无 Web UI、批量调度或人工评分导入。

## 后续真实效果验证

1. 先选 10 条不同场景的本地样本，包括产品展示、人物操作、静态特写、文字遮挡、快速动作。人工先写出事实与关键动作时间范围。
2. 每条先以 1 fps 调用一次，逐项核对描述是否正确、动作是否遗漏、文字是否幻觉、时间是否偏移；必要时对同一视频改为 2 fps 比较。两个 fps 配置分别缓存并可能分别计费。
3. 若结果可用，再扩展至 100～200 条，按场景保留样本分层，避免仅选择容易视频。
4. 使用下列评分表记录结果；mock 样本不计入质量统计。建议预先约定验收目标，例如：有效 JSON ≥95%、关键动作覆盖 ≥90%、严重事实幻觉为零、关键时间点误差中位数 ≤1 秒。这些是待验证目标，不是已达成指标。
5. 根据实际 usage、失败率和人工评分再选择模型，不先启动全量素材库分析。通过后进入 P2 检索验证。

人工记录表模板见 `p1-review-template.csv`。每个模型/fps 组合单独一行，quality 字段人工填写；时间误差应以人工标注与模型实际对应关键时间点比较，不能只凭 JSON 校验判断准确。


## 自动压缩与立即清理

每次未命中缓存的分析都会先生成临时 MP4：H.264、CRF 24、veryfast、移除音频、保持画面比例；横屏限定在 1280×720 内，竖屏限定在 720×1280 内，小视频不放大，尺寸取偶数。保留时间轴，不主动降到 1 fps；API 的 fps 是独立的模型抽帧设置。

FFmpeg 单线程编码以控制本地 CPU 占用。原视频按块计算 SHA256，不一次读入内存。命中结果缓存时不转码、不调用 AI。程序核对压缩前后时长差（容许 0.25 秒），避免明显时间轴变化；边界检查不能替代人工核对动作。

分析成功、API 出错、结果校验失败、压缩失败或超时时，临时目录均由上下文管理器自动删除。只保存 SQLite 描述、usage 与缓存记录，不永久保存压缩视频。原片和用户提供的本地文件始终保留，程序不会删除用户文件。强制杀进程或断电可能留下系统临时目录中的 `ai-video-p1-*`，不承诺这种情况下立即清理；可在确认没有任务运行后清理这些专用目录。

新增参数：`--ffmpeg`（默认 ffmpeg）、`--compression-timeout`（默认 180 秒）、`--temp-dir`（可选，已存在的本地临时目录）。分析输出的 compression 包含原片/副本大小、宽高和压缩配置。CRF 控制画质，不保证固定输出大小，过大的副本会拒绝上传并删除。

示例（默认 mock，不产生 API 费用）：

```bash
python3 -m video_understanding.cli \
  --video '/本地路径/100MB原片.mov' \
  --provider mock
```

改为 `--provider ark` 并配置密钥才会调用真实视频理解。需要本地 FFmpeg 和 FFprobe。当前自动压缩不负责 NAS 限速复制，请先准备稳定本地样本；NAS 自动入库与分析的串联仍待后续实现。

## NAS 写入保护

即使 NAS 账号拥有写权限，也不得将数据库或临时目录配置到 NAS。当前程序强制拒绝网络文件系统上的输出，并拒绝用户输出符号链接及多重硬链接；P0 扫描另要求 NAS 为系统只读挂载。详情见 README 的严格 NAS 保护说明。P1 仅分析稳定本地样本，不删除用户提供的原片。

## 目标素材范围

正式 NAS 素材源仅限共享根目录下的 `抖音自播/` 及其子目录中的视频。其他目录和非视频文件不进入目标检索库。此前 NAS 验收样本位于这个目录内。P1 人工本地样本分析不等同于素材入库；后续 P2 只使用这一范围内的登记素材。
